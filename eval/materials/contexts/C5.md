中文压缩通道离线评测数据集构建与注入流程说明

本文档面向负责 kompress-zh 评测数据准备与离线推理作业运维的工程师，详细描述将任务 A 和任务 C 共十道评测题目注入评测数据库、触发离线推理作业并收集最终评测结果的完整操作流程。整个流程共分六个步骤，各步骤之间存在明确的前置依赖关系，须按照以下顺序严格执行，任何步骤报错后必须修复后方可继续，不得跳过。

第一步：启动离线推理作业所依赖的基础服务

执行命令：sudo systemctl start rabbitmq-server && sudo systemctl start postgresql && sleep 5 && sudo systemctl status rabbitmq-server postgresql | grep -E "active|inactive"

本步骤负责启动两项核心基础服务：消息队列服务 rabbitmq-server 和关系型数据库服务 postgresql。离线推理作业依赖 RabbitMQ 进行任务分发，每道题目被封装为一条消息推入队列，由 Worker 进程消费并执行推理；推理结果则通过 PostgreSQL 进行持久化存储（PostgreSQL 默认监听端口为 5432）。本步骤须等待两个服务均达到 active (running) 状态，才能继续后续步骤。若 rabbitmq-server 或 postgresql 任一服务未能成功启动，须执行 journalctl -u rabbitmq-server 或 journalctl -u postgresql 检查系统日志，排查并修复问题后再重试，在两个服务均正常运行前，不得强行继续执行第二步。

第二步：初始化评测数据库表结构

执行命令：source /workspace/kompress-zh-eval/venv/bin/activate && python scripts/init_db.py --config config/eval_params.yaml --db-host 127.0.0.1 --db-port 5432 --db-name kompress_eval

脚本 init_db.py 负责连接 PostgreSQL 数据库实例 kompress_eval（若数据库不存在则自动创建），并在其中建立评测所需的三张数据表：tasks 表用于存储题目元数据与正文内容，results 表用于存储各题的推理结果与评分信息，anchors 表用于存储各题的锚点字符串信息以便后续自动评分匹配。本步骤须在第一步两项服务均正常运行后方可执行；若 PostgreSQL 服务尚未就绪，脚本将因连接被拒绝而以退出码 3 报错退出，此时须返回第一步检查并修复 postgresql 服务状态，而非直接重试本步骤。

第三步：将十道评测题目及正文材料批量导入数据库

执行命令：source /workspace/kompress-zh-eval/venv/bin/activate && python scripts/ingest_tasks.py --manifest eval_docs/materials/_manifest_AC.json --context-dir eval_docs/materials/contexts/ --db-host 127.0.0.1 --db-port 5432 --db-name kompress_eval

脚本 ingest_tasks.py 读取题目清单文件 _manifest_AC.json，逐题加载 contexts/ 目录下对应的正文文件，将题目元数据（包括 id、question、gold_answer、anchors 列表、rubric 评分标准等字段）与正文内容一并写入数据库的 tasks 表。导入全部成功后，脚本输出"成功导入 10 条任务"并以退出码 0 正常退出。若某道题的 context_file 字段所指向的文件路径在 contexts/ 目录下找不到对应文件，脚本将以退出码 4 中止，须补充该缺失文件后重新执行本步骤。本步骤须在第二步表结构初始化顺利完成（退出码为 0）后方可执行。

第四步：在 screen 持久会话中启动离线推理 Worker

执行命令：screen -S eval-worker && source /workspace/kompress-zh-eval/venv/bin/activate && python scripts/eval_worker.py --config config/eval_params.yaml --concurrency 4 --queue kompress-eval-tasks

Worker 进程在名为 eval-worker 的 screen 会话中持续运行，负责消费 RabbitMQ 队列 kompress-eval-tasks 中的推理任务，并发度设置为 4，即 Worker 同时并行处理四道题目的推理请求。Worker 启动后须保持持续运行状态，直至队列中全部十道题的推理任务均处理完毕，期间不得强行终止进程。若需查看 Worker 的实时运行进度，可通过命令 screen -r eval-worker 重新接入该 screen 会话。本步骤须在第三步题目导入顺利完成（数据库 tasks 表中已有十条记录）后方可执行；若在题目尚未导入时就启动 Worker，Worker 会因队列为空而立即退出，无法执行任何推理任务。

第五步：触发任务分发，将全部十道题推入消息队列

执行命令：source /workspace/kompress-zh-eval/venv/bin/activate && python scripts/dispatch_tasks.py --db-host 127.0.0.1 --db-port 5432 --db-name kompress_eval --queue kompress-eval-tasks --task-set AC

脚本 dispatch_tasks.py 从数据库 tasks 表中读取任务集 AC 下的全部十道题，将每道题封装为标准 JSON 格式的消息，并逐条推送至 RabbitMQ 队列 kompress-eval-tasks。全部十条消息推送完毕后，脚本输出确认信息"已分发 10 条任务至队列 kompress-eval-tasks"。建议在第四步 Worker 已经在 screen 会话中正常运行后再执行本步骤，这样消息一旦入队即可被立即消费处理，便于通过 Worker 会话实时监控各题的推理进度；若 Worker 尚未启动就先执行本步骤完成分发，消息会积压在队列中等候，待 Worker 启动后同样可以正常消费，但进度监控会有一定延迟。

第六步：等待全部推理完成并生成评分报告

执行命令：source /workspace/kompress-zh-eval/venv/bin/activate && python scripts/wait_and_score.py --db-host 127.0.0.1 --db-port 5432 --db-name kompress_eval --expected-tasks 10 --timeout 7200 && python scripts/gen_report.py --result-dir /workspace/kompress-zh-eval/results/ --output /workspace/kompress-zh-eval/report/eval_report_AC.html

脚本 wait_and_score.py 以每隔三十秒一次的频率轮询数据库 results 表，持续等待直至全部十道题的推理结果均写入完毕，或达到最大等待时限（7200 秒即两小时）。全部结果到齐后，脚本自动调用 gen_report.py 生成 HTML 格式的完整评分报告，报告保存路径为 /workspace/kompress-zh-eval/report/eval_report_AC.html，报告内容包含各题的原始答案、标准答案、锚点命中情况及最终评分。若在等待超时前仍有题目的推理结果未写入数据库，wait_and_score.py 将以退出码 2 退出，此时应先检查第四步 Worker 进程是否仍在正常运行，再确认第五步是否已将全部十道题成功推入队列，排查根本原因后重新触发未完成题目的推理任务。
