# AutoDL 复现交接说明——已知命令参考与浏览器访问方式

本节整理在当前已验证的 AutoDL 环境中，操作代理、查看 dashboard 所需的核心命令，供接手队友直接使用。所有命令均经过实际运行验证，请按原文使用，不要随意修改路径或端口。

## 一、启动代理路径

启动完整 demo 代理（包括 bootstrap 隔离环境）：

```bash
export OPENAI_API_KEY="your_key"
bash scripts/start_autodl_codex_gpt54_demo.sh
```

该脚本会完成以下工作：
- 读取或要求 API 密钥（优先从 `ENV_FILE=/root/.config/headroom-zh/env.sh` 加载）
- 设置 `PYTHON_BIN=/root/autodl-tmp/qwen_ws/.venv/bin/python` 作为 Python 解释器
- 设置 `HF_ENDPOINT=https://hf-mirror.com` 确保模型 artifact 加载可达
- 设置 `HEADROOM_REQUIRE_RUST_CORE=false` 明确使用 Python-first 路径
- 隔离 `HEADROOM_WORKSPACE_DIR`、`CODEX_HOME`、`HOME` 三个目录，防止旧状态污染
- 在 screen 会话中后台启动代理，会话名固定为 `hrzh_demo_8790`
- 等待代理在端口 `8790` 上就绪后才继续后续步骤

脚本启动后，预期 dashboard 初始状态：`tokens_saved = 0`，`requests_total = 0`，`text_count = 0`，`ws_units_modified = 0`。

## 二、启动 Codex 客户端

代理就绪后，在隔离路径上启动 Codex CLI：

```bash
bash scripts/launch_autodl_codex_gpt54.sh
```

该脚本负责：
- 设置 `PATH=/root/.headroom/bin:/opt/node-v22/bin:$PATH`，使 `codex` 和 `rtk` 均可调用
- 将 Codex 指向本地代理（端口 `8790`），上游为 `https://yunwu.ai/v1`，模型为 `gpt-5.4-2026-03-05`
- 在隔离的 `CODEX_HOME` 下运行，避免全局 Codex 配置干扰

## 三、查看代理 screen 会话

代理以 screen 后台方式运行。附加到会话查看实时日志：

```bash
screen -r hrzh_demo_8790
```

如果该名称不存在，先检查当前所有 screen 会话：

```bash
screen -list
```

若 `hrzh_demo_8790` 会话不在列表中，说明代理尚未启动或已意外退出，需要重新运行启动脚本。

## 四、浏览器本地端口转发

AutoDL 机器上的 dashboard 不能直接在本地浏览器访问。需要在本地机器上执行 SSH 端口转发：

```bash
ssh -CNg -L 8790:127.0.0.1:8790 root@connect.nmb1.seetacloud.com -p 47263
```

命令参数说明：
- `-CNg`：不执行远程命令，仅建立转发隧道，允许非本地绑定。
- `-L 8790:127.0.0.1:8790`：将本地 8790 端口映射到远程机器的 127.0.0.1:8790。
- `root@connect.nmb1.seetacloud.com`：AutoDL 实例的 SSH 主机地址。
- `-p 47263`：AutoDL 实例的 SSH 端口号（非标准 22 端口）。

端口转发建立后，在本地浏览器打开：

- `http://localhost:8790/dashboard`——主 dashboard，显示 token 节省总量、实时统计。
- `http://localhost:8790/stats-history`——历史统计，可追溯每次请求的累计变化。

其他可用 dashboard 端点（可在 curl 或浏览器中访问）：

- `/readyz`——就绪探针，返回代理是否已初始化完毕。
- `/stats`——当前原始统计 JSON，包含 `tokens_saved`、`requests_total`、`compressions_by_strategy` 等字段。

## 五、常见失败场景与处理

**代理始终未就绪（`proxy did not become ready on port 8790`）**：首先附加到 screen 会话 `hrzh_demo_8790` 查看运行时日志，不要在没有看日志之前就随意改变多个变量。常见原因包括：模型冷加载耗时过长、Python 环境缺包、`PYTHON_BIN` 路径与实际不符、网络侧初始化失败。

**dashboard 非零启动**：说明 workspace 目录隔离未生效，存在旧状态泄漏。检查 `HEADROOM_WORKSPACE_DIR`、`CODEX_HOME_DIR`、`CODEX_USER_HOME_DIR` 三个目录是否真正被清空或隔离。

**Codex 配置警告**：Codex 可能打印 `Ignored unsupported project-local config keys` 警告，这在当前已验证路径中属于已知非阻塞问题，不要将其误判为隔离 demo 路径失败的证据。

**WebSocket 噪声**：启动或探针运行期间偶发握手或传输警告，属于已知非阻塞现象。判断标准应为：turn 是否完成、`/stats` 是否有变化、`/dashboard` 是否反映了本次运行。

## 六、端口与会话命名规范说明

当前演示方案中，所有涉及端口号、screen 会话名、SSH 命令的值均为固定值，不应随意修改：

推荐演示端口统一为 `8790`，与之对应的 screen 会话名固定为 `hrzh_demo_8790`，SSH 端口转发命令中的远程 SSH 端口号固定为 `47263`，SSH 主机为 `connect.nmb1.seetacloud.com`。这四个值组合在一起，构成了当前 AutoDL 演示实例的完整访问坐标。

端口 `8790` 的选择并非随意，而是经过隔离设计：每个端口对应一套独立的工作区目录，保证不同演示实例之间的计数和状态完全隔离。在实际演示录制中，使用固定端口意味着可以在事前重置该端口的 workspace，确保演示从零开始，数字增长过程完整可见，这是演示效果的核心保障。

screen 会话名包含端口号（`hrzh_demo_8790`）的命名规范，使得多个演示实例并存时，任何队友都能通过会话名直接判断哪个会话对应哪个端口，无需额外查询。这在多人协作的 AutoDL 环境中减少了沟通成本。

SSH 端口转发命令中的 `-p 47263` 是 AutoDL 当前实例分配的 SSH 端口，是平台决定的，不是项目配置项。如果实例更换或重启，该端口号可能发生变化，届时需要从 AutoDL 控制台重新获取正确的 SSH 连接参数。
