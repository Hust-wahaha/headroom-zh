模型缓存预热服务迁移操作手册（从旧节点 cache-node-03 迁移至新节点 cache-node-09）

本手册适用于将生产环境模型缓存服务从 cache-node-03（IP：10.8.3.3）整体迁移至 cache-node-09（IP：10.8.9.1）的场景。迁移过程分为以下 6 个步骤，各步骤之间存在严格依赖，操作人员须按序执行，不得乱序。

步骤一：在新节点安装并启动 Redis 与模型缓存服务基础组件
在 cache-node-09 上执行：sudo apt-get install -y redis-server && sudo systemctl enable redis-server && sudo systemctl start redis-server
验证：执行 redis-cli -h 127.0.0.1 -p 6379 ping，返回 PONG 则表示 Redis 就绪。若 Redis 未正常启动，后续步骤所有涉及缓存写入的操作均无效，必须修复后方可继续。

步骤二：从旧节点导出缓存索引快照
在 cache-node-03 上执行：bash /opt/model-cache/scripts/export_index.sh --output /tmp/cache_index_snapshot_20260622.tar.gz
说明：该脚本将当前缓存目录 /data/model-cache/ 的文件索引（不含权重文件本身）打包为快照。注意：此步骤必须在步骤一完成后执行，以确保新节点 Redis 已就绪可接收后续导入。若旧节点上有未完成的拉取任务（task_status/ 目录下存在状态为 running 的 .json 文件），须先等待任务完成或手动中止后再执行本步骤。

步骤三：将快照传输至新节点并验证完整性
在 cache-node-03 上执行：scp /tmp/cache_index_snapshot_20260622.tar.gz headroom@10.8.9.1:/tmp/
传输完成后，在 cache-node-09 上执行：sha256sum /tmp/cache_index_snapshot_20260622.tar.gz
将校验值与 cache-node-03 上 sha256sum /tmp/cache_index_snapshot_20260622.tar.gz 的输出对比，两者必须完全一致，否则文件在传输过程中损坏，须重新传输，不可继续执行步骤四。

步骤四：在新节点导入缓存索引并执行本地验证
在 cache-node-09 上执行：bash /opt/model-cache/scripts/import_index.sh --input /tmp/cache_index_snapshot_20260622.tar.gz --cache-dir /data/model-cache/
说明：导入脚本会将索引写入 Redis 并验证条目完整性。执行完成后会输出导入条目数量和失败条目数量，若失败条目数量大于 0，须查看脚本输出的错误详情，决定是否可接受后再进入下一步。本步骤是步骤三之后的直接延续，在文件完整性未通过步骤三验证之前，严禁执行本步骤。

步骤五：切换流量路由——将上游服务指向 cache-node-09
在网关节点上执行：bash /opt/headroom-zh/scripts/switch_cache_node.sh --from 10.8.3.3 --to 10.8.9.1 --port 7300
说明：该脚本会原子性地修改网关路由配置，使所有新进入的模型缓存请求均路由至 cache-node-09:7300。切换完成后，脚本自动发送 10 次探针请求验证新节点响应，若探针成功率低于 80%（即 10 次中失败超过 2 次），脚本将自动回滚到 cache-node-03，并退出码 5，此时不应继续步骤六，须先排查新节点问题。

步骤六：下线旧节点缓存服务
在 cache-node-03 上执行：sudo systemctl stop model-cache-puller && sudo systemctl disable model-cache-puller
说明：本步骤须在步骤五流量切换成功（探针成功率 ≥80%，脚本退出码为 0）且新节点运行稳定至少 15 分钟后方可执行。过早下线旧节点可能导致进行中的模型文件服务请求中断，影响在线推理服务。下线后可选择保留 /data/model-cache/ 目录内容 7 天作为回滚备份，7 天后再彻底清理。
