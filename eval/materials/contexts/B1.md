# AutoDL 复现交接说明——环境假设与脚本前提

本文档为接手 headroom-zh AutoDL 演示路径的队友整理，内容忠实对应真实复现指南，请逐条核对后再动手操作。

## 一、当前已验证内容

当前在已准备好的 AutoDL 环境中，以下事项均已得到实际验证：

- `kompress_zh` 中文压缩分支在真实 Codex 运行路径中已激活，可在阅读密集型任务中产生可见的 token 节省量。
- `/stats`、`/dashboard`、`/stats-history` 三个 dashboard 端点均能正确反映运行活动。
- demo bootstrap 通过隔离 `HEADROOM_WORKSPACE_DIR`、`HOME`、`CODEX_HOME` 三个目录变量，确保端口间状态不互相污染，dashboard 计数从零开始干净增长。
- 当前推荐的 demo 演示端口为 `8790`，已在独立清零 workspace 下完成真实 Codex 阅读任务的完整记录。

## 二、Python 环境假设

启动脚本 `scripts/start_autodl_codex_gpt54_demo.sh` 对 Python 路径做了固定假设：

```bash
PYTHON_BIN=/root/autodl-tmp/qwen_ws/.venv/bin/python
```

该路径指向一个已预先创建的 Python 虚拟环境。脚本假设：虚拟环境已存在；Headroom 仓库可从该解释器导入；代理运行路径所需的所有运行时包均已安装完毕。

**重要警告**：如果新机器上该虚拟环境不存在，脚本不会自动为你创建它。你必须先手动指定 `PYTHON_BIN` 或重新搭建等效环境，否则代理启动会在 Python 初始化阶段即失败。

## 三、Node / Codex 路径假设

启动路径假设 Node 可执行文件位于 `/opt/node-v22/bin`，RTK 工具位于 `/root/.headroom/bin`。完整路径拼接为：

```bash
PATH=/root/.headroom/bin:/opt/node-v22/bin:$PATH
```

随后直接调用 `codex` 命令。这意味着：Node 必须已安装在 `/opt/node-v22/bin`；`codex` CLI 在该环境中必须已安装且可调用；`rtk` 必须可在 `/root/.headroom/bin` 下找到。

与 Python 路径的情况相同——demo 脚本不会在全新机器上自动安装上述所有组件。

## 四、API 密钥与环境变量文件

两个 demo 脚本均尝试读取以下路径的环境变量文件：

```bash
ENV_FILE=/root/.config/headroom-zh/env.sh
```

如果该文件存在，脚本会自动 source 它。如果该文件不存在，则要求 `OPENAI_API_KEY` 已在当前 shell 中导出。最低要求：

```bash
export OPENAI_API_KEY="..."
```

如果密钥缺失，脚本会提前主动失败，不会静默跳过。这是有意设计，防止因密钥缺失而造成难以追踪的后续错误。

## 五、HuggingFace 镜像假设

bootstrap 脚本将 HuggingFace 端点设置为：

```bash
HF_ENDPOINT=https://hf-mirror.com
```

这一设置在当前已验证环境中属于实际路径的一部分，并非可选的装饰性配置。在新环境中：若没有更好的可达镜像，应保持此设置；若模型缓存是冷启动状态，预期首次加载会较慢；若镜像访问不稳定，则可能发生加载失败。

## 六、Rust core 绕过假设

当前已验证路径明确使用：

```bash
HEADROOM_REQUIRE_RUST_CORE=false
```

当前 AutoDL 演示路径是以 Python 为主的路径，并非 Rust core 的重新构建。在 Python 路径稳定之前，不要花时间去证明 Rust 等价性。这一区分对于快速复现而言至关重要，混淆两条路径只会浪费调试时间。

## 七、上游模型与代理端点

当前验证通过的上游配置为：

- 上游 API 地址：`https://yunwu.ai/v1`
- 使用模型：`gpt-5.4-2026-03-05`

请不要在当前 Codex 演示路径上切换为 DeepSeek 或其他模型——问题不在于模型质量，而在于 Yunwu 对 Codex 所使用的 `/v1/responses` 路由的支持情况。使用不支持该路由的模型会导致路径失效，并产生难以区分是压缩问题还是上游问题的错误现象。
