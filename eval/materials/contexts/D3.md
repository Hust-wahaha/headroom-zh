# kompress_zh 集成笔记——验证状态记录与回归测试覆盖

本文为集成笔记中文化版本，记录 `kompress_zh` 在 AutoDL 环境中的验证状态、回归测试覆盖要求，以及各类结论的置信程度。本文的关键价值在于：明确区分"已在特定环境中验证"与"可在任意环境普遍适用"这两个层面，这是语义精度的核心要求。

## 一、验证状态：已在 AutoDL 远程环境确认的事项

集成验证于 2026-06-14 和 2026-06-15 在 AutoDL 远程环境中完成。在此次验证中，以下事项得到确认：

**环境条件**：
- 真实的 base model 缓存已存在于目标机器上
- 真实的 adapter checkpoint 被实际使用（不是 mock）

**验证结果**：
- 英文路由确认独立运行：英文内容走原有 `Kompress` 路径，不受 `kompress_zh` 集成影响。
- 中文路由产出实际压缩文本：中文主导的工具输出被正确路由到 `kompress_zh`，并返回经过压缩的结果（而非 passthrough）。
- OpenAI 风格 `tool` 消息路径通过 `ContentRouter.apply(...)` 级别验证。
- content-block `tool_result` 路径通过 `ContentRouter.apply(...)` 级别验证。

**观察到的特征标记**：
- 压缩后的输出包含 `router:text:...` 前缀标记
- 路由记录包含 `router:tool_result:text` 标记
- 中文工具输出被压缩接受，没有回退到 passthrough

## 二、应当保留的回归测试覆盖

在 `tests/test_transforms/test_content_router.py` 中，以下测试必须保留：

- **中文主导检测器测试**：验证 `_is_chinese_dominant_text(...)` 对各类输入的判定结果正确。
- **英文文本走原有路径测试**：确认英文内容使用 `_get_kompress`（旧路径），而非 `_get_kompress_zh`。
- **中文文本走新路径测试**：确认中文主导内容使用 `_get_kompress_zh`（新路径）。

保留理由：这些是值得固化的最小路由回归覆盖。路由分叉逻辑一旦出错，会导致：①中文内容走错路径（退化为英文压缩器处理，效果差）；②英文内容意外进入中文压缩器（产出质量不可预期）。这两种故障都不易从外部观察发现，因此路由层的回归测试具有实质价值。

## 三、不应沿用的做法

### 3.1 用 README 措辞暗示架构发生了全量替换

不应将本次集成描述为"kompress_zh 替换了 Kompress"。这类措辞会误导下游开发者，让其认为英文压缩路径已不再维护或已被废弃，从而影响他们对架构的判断和后续决策。正确的表述是：两条路径并行存在，按语言类型分别路由。

### 3.2 将 AutoDL 专用验证脚本当作测试基础设施提交

AutoDL 专用的 smoke 验证脚本（如 `scripts/smoke_autodl_headroom.py`）是在特定部署环境中快速验证路径联通性的工具，不是通用的自动化测试基础设施。将其纳入 CI/CD 流程或作为正式测试套件提交，会产生以下问题：①它依赖 AutoDL 特有的环境假设，在其他环境中无法运行；②它混淆了"验证产物"与"产品测试"的边界。

## 四、仍存在不确定性的事项

### 4.1 验证结论仅适用于已准备好的 AutoDL 环境

这是本文档的核心限制声明，需要特别强调：**2026-06-14/15 的验证结论仅适用于当时已准备好的 AutoDL 环境，不代表该路径已在任何全新机器上从零完整复现。**

具体来说：
- 验证时 base model 缓存已存在，adapter checkpoint 已就位，Python 虚拟环境已搭建。
- 如果在一台真正空白的 AutoDL 机器上从零开始，需要重新处理模型拉取、环境搭建、依赖安装等步骤，这些步骤的可重复性尚未在冷环境下系统验证。

这一区分非常重要，因为评委可能会问："是否已在全新机器上验证过？"。正确答案是：**在已准备好的环境中验证过；在全新空白机器上的端到端复现尚未系统完成。**

### 4.2 本地 Windows pytest 不可信的影响范围

本地 Windows 开发机上的 `pytest` 因缺少 `headroom._core` 和 `tiktoken` 而无法全量运行。这意味着：在 Windows 上跑通的单元测试不能代表在 AutoDL Linux 环境中的行为，开发时需要对"本地测试通过"的结论保持谨慎态度。这是当前开发环境局限性的诚实记录，不影响 AutoDL 上的实际运行验证结论。
