# AutoDL 复现交接说明——SSH 端口转发、dashboard 端点与仍未完全确认的事项

本节整理浏览器访问 dashboard 的完整 SSH 端口转发操作，说明各 dashboard 端点的用途，并如实列出当前尚未完全验证、不应过度宣称的内容。最后一节是接手队友的推荐工作顺序。

## 一、SSH 本地端口转发的完整命令

AutoDL 实例不直接对外暴露 Web 端口，需要在本地机器执行 SSH 端口转发才能在浏览器中访问 dashboard。完整命令为：

```bash
ssh -CNg -L 8790:127.0.0.1:8790 root@connect.nmb1.seetacloud.com -p 47263
```

各参数含义：
- `-C`：启用 SSH 数据压缩（对 HTTP dashboard 流量有轻微帮助）。
- `-N`：不执行任何远程命令，纯端口转发模式。
- `-g`：允许远程主机连接到本地转发端口（即非 localhost-only 绑定）。
- `-L 8790:127.0.0.1:8790`：将本地端口 `8790` 通过 SSH 隧道映射到远程机器的 `127.0.0.1:8790`。
- `root@connect.nmb1.seetacloud.com`：AutoDL 实例的 SSH 主机名，当前实例为 `connect.nmb1.seetacloud.com`。
- `-p 47263`：AutoDL 实例使用的 SSH 端口号，注意这不是标准 22 端口，而是 `47263`。

**Windows 本地 SSH 配置问题**：在 Windows 本地机器上运行上述命令时，可能遇到 SSH config 权限错误。这是本地客户端侧问题，与服务端 Headroom 代理无关。修复方式取决于本机配置，不在本文档规定范围内。

## 二、各 dashboard 端点的用途

代理在端口 `8790` 上暴露以下端点：

### `/dashboard`
主 dashboard，提供可视化界面，显示：
- 当前 session 累计节省的 token 数
- 压缩请求总数
- 按策略分类的压缩次数

演示时首先访问此页面，确认从零起步后随 Codex 运行逐步增长。

### `/stats-history`
历史统计端点，展示每次请求对应的统计变化趋势，适合演示"运行前后对比"场景。

### `/stats`
原始 JSON 统计端点，包含以下关键字段：
- `tokens_saved`：生命周期内节省的 token 总量
- `requests_total`：处理的请求总数
- `compressions_by_strategy`：按压缩策略分类的次数统计
- `codex_ws.units_modified_total`：WebSocket 路径中被修改的单元总数
- `codex_ws.unit_tokens_saved_sum`：WebSocket 路径节省的 token 总量

### `/readyz`
就绪探针端点，返回代理是否已完成初始化。smoke 测试脚本 `scripts/smoke_autodl_headroom.py` 使用此端点判断代理是否可以接受请求。

## 三、当前尚未完全验证的内容

以下事项在复现文档中明确列为"尚不确定"，不应对外过度宣称：

**全新空白机器端到端复现**：当前验证基于**已准备好的 AutoDL 环境**，不代表已有文档能够指导一台完全空白的 AutoDL 新机器从零重建全部路径——包括 Python 虚拟环境重建、Node/Codex 安装、所有依赖包拉取、模型缓存状态复现等。这一"blank AutoDL machine bootstrap checklist"尚需有人实际从冷环境走完一遍再确认。

**最小依赖集尚未冻结**：脚本表达了一些假设，但一台全新机器所需的最小可复现环境规格，目前尚未写成单一的逐步安装配方。

**Rust native 等价性有意推迟**：如果有人希望先重建 Rust core，这是一个独立的工程任务，不是复现当前中文演示的最快路径。

## 四、接手队友的推荐工作顺序

1. 先完整阅读本交接文档。
2. 再阅读 `docs/HEADROOM_ZH_STATUS_2026-06-20.md`——这是当前项目最新验证状态的权威记录。
3. 执行 Level 0 环境检查和 Level 1 smoke 测试，确认基础环境正常，再考虑接触真实 Codex 路径。
4. smoke 稳定后，再执行 `scripts/start_autodl_codex_gpt54_demo.sh`。
5. 遇到新的环境特定修复，请记录在有日期的笔记中，不要静默修改多处文档而不留痕迹。

如果下一步需要改善文档，最有价值的工作是：在真正从冷环境重走一遍之后，补充一份独立的"全新 AutoDL 机器 bootstrap 检查清单"，而不是现在凭推测提前写出来。

## 五、演示数据参考

在已完成的真实演示运行中，从干净的 `8790` 实例出发（初始全部为零），经过一次真实的中文文档阅读密集型 Codex session 后，记录到以下统计：

- `tokens_saved = 27866`
- `requests_total = 10`
- `text_count = 12`
- `ws_units_modified = 49`
- `ws_unit_saved = 27668`
- `ws_frame_saved = 27866`

`proxy_savings.json` 中的 `lifetime_tokens_saved` 与 `/stats` 端点中的值一致，均为 `27866`。这是当前最具说服力的演示级证据，因为它从零起步，在真实 Codex session 中可见地增长。
