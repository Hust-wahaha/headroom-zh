# AutoDL 复现交接说明——复现阶梯与分级执行策略

本节为接手队友整理"复现阶梯"操作规范，说明为何不能跳过任何一级直接进入完整 Codex 演示，以及每一级的具体验证目标。

## 一、总体原则：不要跳级

在新环境（或部分全新环境）上进行复现时，绝对不要直接从零跳到完整 Codex 演示。正确做法是按阶梯逐级推进，每一级有明确的验证目标和"未通过则不得进入下一级"的门控条件。

整个复现阶梯共分四级：

- **Level 0**：环境检查（Environment Inspection）
- **Level 1**：smoke 路径单独验证（Smoke Path Only）
- **Level 2**：隔离代理 bootstrap（Isolated Proxy Bootstrap）
- **Level 3**：真实 Codex 路径（Real Codex Path）

## 二、Level 0：环境检查

在运行任何脚本之前，先确认以下基础环境项目均已就绪：

- `PYTHON_BIN` 对应路径是否存在？即 `/root/autodl-tmp/qwen_ws/.venv/bin/python` 是否可访问？
- `codex` 命令是否可调用？
- Node 路径 `/opt/node-v22/bin` 是否存在？
- 环境变量文件 `/root/.config/headroom-zh/env.sh` 是否存在？
- 仓库路径是否在你预期的位置？

建议执行以下检查命令：

```bash
ls /root/autodl-tmp/qwen_ws/.venv/bin/python
which codex
ls /opt/node-v22/bin
cat /root/.config/headroom-zh/env.sh
```

如果上述基础检查有任何一项失败，请先修复它，而不是去调试代理行为。把底层环境问题误判为代理 bug 是最常见的时间浪费来源。

## 三、Level 1：smoke 路径验证

环境检查通过后，首先单独运行 smoke 测试：

```bash
python scripts/smoke_autodl_headroom.py
python scripts/smoke_autodl_headroom.py --expect-kompress
```

Level 1 的特点与价值在于：
- 使用模拟上游（mock upstream），不依赖真实 API 密钥或 Yunwu 服务可达性。
- 验证本地代理是否能正常启动。
- 验证 `/readyz`、`/dashboard`、`/stats-history` 这三个关键端点是否响应正常。
- 避免在过早阶段将 Codex 运行时问题与代理/运行时问题混在一起，使故障定位更困难。

**关键门控规则**：如果 Level 1 的 smoke 测试失败，绝对不可以继续推进到 Level 2 或 Level 3。原因是：smoke 失败意味着代理本身存在问题，此时引入 Codex 只会增加干扰变量，让问题更难追踪。

## 四、Level 2：隔离代理 bootstrap

smoke 验证通过后，启动真实的代理 bootstrap：

```bash
export OPENAI_API_KEY="your_key"
bash scripts/start_autodl_codex_gpt54_demo.sh
```

Level 2 的验证目标：
- 代理是否已在端口 `8790` 上就绪？
- screen 会话是否已创建（会话名为 `hrzh_demo_8790`）？
- `/readyz` 端点是否正常响应？
- `CODEX_HOME` 配置文件是否已生成？
- dashboard 是否从零开始（即 `tokens_saved = 0`，`requests_total = 0`）？

如需查看代理运行日志，可附加到 screen 会话：

```bash
screen -r hrzh_demo_8790
```

## 五、Level 3：真实 Codex 路径

代理 bootstrap 成功、Level 2 验证点全部通过后，才可启动真实 Codex 路径：

```bash
bash scripts/launch_autodl_codex_gpt54.sh
```

Level 3 的注意事项：必须使用**阅读密集型**任务场景。不要使用短小或通用任务，因为那类任务会让系统看起来没有产生压缩效果，即便路径本身技术上完全正常。推荐的演示案例顺序为：`case_01_docs_review`（最清晰的中文阅读密集型场景）→`case_03_codebase_explore`→`case_02_log_triage`。

## 六、Level 1 失败时的处理策略

Level 1 smoke 失败不可跳过的另一层原因：smoke 使用 mock 上游，排除了网络、API 密钥、上游模型等所有外部变量。如果连 mock 环境下的本地代理都无法通过，说明 Python 环境、代理启动逻辑、端口绑定或路由初始化存在本质性问题。在这些问题解决之前进入 Level 3，会让你在三个以上维度同时调试，大幅增加定位难度。正确做法是：在 Level 1 框架内彻底诊断并修复问题，确认 smoke 完全通过后再前进。
