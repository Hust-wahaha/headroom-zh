headroom-zh v0.8.3 完整部署流程说明

本文档面向在全新 Ubuntu 22.04 宿主机上首次部署 headroom-zh 代理服务的工程师。部署工作是一项有严格顺序要求的操作，各步骤之间存在不可逾越的前置依赖关系，必须按照以下列出的顺序逐步执行，不可跳过任何步骤，也不可调换步骤顺序，否则将导致后续步骤因缺少前置条件而失败，产生难以诊断的错误。文档中的每一步均给出了需要执行的命令原文以及详细的说明，请工程师在操作前认真阅读说明，充分理解每一步的意图与依赖关系，再执行对应的命令。

第一步：安装系统级依赖

需要执行的命令为：sudo apt-get install -y git python3.11 python3.11-venv python3-pip cmake libmecab-dev redis-server

此步骤安装所有运行和编译所需的系统级组件：git 用于代码克隆，Python 3.11 提供运行时环境，cmake 是 sentencepiece 包源码编译的必要前置工具（若缺少 cmake，第三步 pip 安装将以错误码 BUILD-2051 失败），libmecab-dev 用于 fugashi 日语分词绑定，redis-server 安装后由 systemd 自动启动并默认监听 127.0.0.1:6379。若本步骤出现任何错误，后续全部步骤均无法正常执行，须修复后重试，不可强行继续。

第二步：克隆代码仓库并切换至目标版本

需要执行的命令为：git clone https://git.internal.example.com/headroom-zh.git /opt/headroom-zh && cd /opt/headroom-zh && git checkout v0.8.3

本步骤将仓库克隆至目录 /opt/headroom-zh，并切换至正式发布标签 v0.8.3。若标签不存在，说明版本尚未发布，应立即停止部署流程。本步骤须在第一步成功安装 git 后执行，pyproject.toml 和 requirements.txt 等依赖清单文件均随代码仓库一并到位，为第三步做好准备。

第三步：创建 Python 虚拟环境并安装所有 Python 依赖

需要执行的命令为：python3.11 -m venv /opt/headroom-zh/venv && source /opt/headroom-zh/venv/bin/activate && pip install -e ".[dev]"

本步骤在 /opt/headroom-zh/venv/ 目录下创建 Python 虚拟环境，激活后安装项目全部依赖，包括 fastapi、uvicorn、tiktoken、pydantic、sentencepiece 等。sentencepiece 的源码编译依赖第一步安装的 cmake，若第一步未成功安装 cmake，本步骤将在 sentencepiece 编译阶段报错并以错误码 BUILD-2051 终止，此时须返回第一步补装 cmake，不可跳过此问题继续推进到第四步。

第四步：初始化配置目录并填写关键环境变量

需要执行的命令为：sudo mkdir -p /root/.config/headroom-zh && sudo cp /opt/headroom-zh/config/env.sh.template /root/.config/headroom-zh/env.sh && sudo nano /root/.config/headroom-zh/env.sh

本步骤将配置模板复制为 /root/.config/headroom-zh/env.sh，随后用编辑器手动填写以下必填变量：OPENAI_API_KEY（必须填写，留空将导致预检在第五步以错误码 CFG-4031 失败），HEADROOM_LISTEN_PORT（默认值为 9087，若该端口已被其他进程占用需修改为其他可用端口），HEADROOM_LOG_LEVEL（生产环境建议设为 INFO）。本步骤须在第三步完成、代码仓库中的 config/env.sh.template 模板文件已就位后执行。

第五步：执行 Level 1 Smoke 配置校验

需要执行的命令为：source /opt/headroom-zh/venv/bin/activate && python scripts/validate_config.py

本步骤是 Level 1 Smoke 检测，校验脚本将依次检查全部 35 条配置规则，重点核查 OPENAI_API_KEY 是否已在 /root/.config/headroom-zh/env.sh 中定义、compression_algorithm 字段值是否在合法枚举 [bm25, tfidf, llmlingua] 范围内（实例配置 /opt/headroom-zh/config/instance.toml 的默认预设值为 llmlingua）等关键配置项。本步骤必须以退出码 0 通过，方可进入第六步启动服务。若退出码非 0，必须依据错误码和日志提示修复配置后重新执行本步骤，禁止在 Level 1 Smoke 未通过的情况下直接执行第六步。

第六步：启动代理服务

需要执行的命令为：source /opt/headroom-zh/venv/bin/activate && bash scripts/start_proxy.sh

本步骤由脚本读取 /root/.config/headroom-zh/env.sh 中的环境变量，绑定 HEADROOM_LISTEN_PORT 指定的端口（默认 9087），拉起 uvicorn 进程对外提供代理服务。启动日志写入 /var/log/headroom-zh/startup_*.log。若绑定时出现 EADDRINUSE 错误，说明目标端口已被占用，须处理端口冲突后重新执行本步骤。

第七步：Level 2 连通性与压缩功能验证

需要执行的命令为：bash scripts/run_smoke_tests.sh --level 2 --host 127.0.0.1 --port 9087

本步骤在 Level 1 Smoke（第五步）已通过且服务已正常启动（第六步）的前提下执行。测试脚本向本地代理端口 9087 发送真实推理请求，验证中文压缩通道是否正常工作。测试结果写入 /var/log/headroom-zh/smoke_level2_*.json。若 Level 2 测试失败，不得对外开放服务入口，须先排查日志再决定是否重试或回滚。
