# AutoDL 复现交接说明——Rust core 旁路、模型选择与关键环境变量

本节聚焦于三个容易被误解的技术决策：Rust core 被有意绕过的原因、模型锁定为 `gpt-5.4-2026-03-05` 的理由、以及几个关键环境变量的精确值与语义。这些决策在全新机器上复现时必须原样保留，否则会引入难以归因的问题。

## 一、Rust core 旁路：为什么设置为 false

当前已验证路径中，环境变量明确设置为：

```bash
HEADROOM_REQUIRE_RUST_CORE=false
```

这是有意的、经过判断的决策，不是权宜之计。理由如下：

当前 AutoDL 演示路径的定位是**Python-first**，即以 Python 实现的代理路径为核心，Rust core 的并行重建属于独立的工程任务。如果在 Python 路径尚未稳定的情况下，强行要求 Rust core 可用，会在两个维度同时引入不确定性。设置 `HEADROOM_REQUIRE_RUST_CORE=false` 明确告诉运行时：不依赖 Rust core，使用 Python fallback 路径。这样，如果代理出现问题，可以把排查范围锁定在 Python 环境内，不需要同时调查 Rust 编译和链接问题。

**注意事项**：在新机器上复现时，不要把这个值改回 `true`，除非你已经专门为 Rust core 路径做好了完整准备。改变这个值并不会带来任何好处，只会增加复现失败的概率。

## 二、模型锁定：为什么必须用 `gpt-5.4-2026-03-05`

当前 Codex 演示路径锁定的上游配置为：

- 上游地址：`https://yunwu.ai/v1`
- 模型：`gpt-5.4-2026-03-05`

该组合的核心约束来自 Yunwu 对 Codex 所使用的 `/v1/responses` 路由的支持情况。Codex CLI 使用的不是标准 `/v1/chat/completions` 接口，而是 `/v1/responses` 路由——这是一个并非所有上游提供商都支持的接口。

**为什么不能切换到 DeepSeek**：在当前 Codex 演示路径上不能切换到 DeepSeek，原因不是模型质量的问题，而是 Yunwu 平台对 `/v1/responses` 路由的模型覆盖问题。如果切换模型导致该路由失效，会产生难以区分是"压缩通道问题"还是"上游支持问题"的混淆故障现象，使演示复现完全失去意义。

## 三、HuggingFace 镜像的实际意义

环境变量：

```bash
HF_ENDPOINT=https://hf-mirror.com
```

在已验证的 AutoDL 环境中，这个设置属于实际路径必要组件，而非可选配置。背景：`kompress_zh` 的推理路径（通过 `PeftModel.from_pretrained(...)` 加载 LoRA adapter）在早期版本中存在一个问题——即使 adapter 文件已在本地缓存中存在，该调用仍可能触发 HuggingFace 元数据查询。在 AutoDL 代理运行时环境中，如果该查询失败（网络侧连接错误），系统会静默回退到 passthrough 模式，表现上看起来像路由失败，实际上是加载器失败。当前修复方案：先将 LoRA adapter 解析为本地 snapshot，再用 `local_files_only=True` 加载。即便如此，保持 `HF_ENDPOINT=https://hf-mirror.com` 仍然是实际可达性的保障。

## 四、环境变量文件路径的精确值

两个演示脚本均从同一位置读取 API 密钥和环境配置：

```bash
ENV_FILE=/root/.config/headroom-zh/env.sh
```

该文件如果存在，会被 source 进当前 shell 环境。最低要求是其中包含：

```bash
export OPENAI_API_KEY="..."
```

如果该文件不存在，需要在运行脚本之前在 shell 中手动导出 `OPENAI_API_KEY`。脚本会在启动早期检测密钥是否存在，若缺失则立即失败退出，不会在后续步骤中才报错。

## 五、PATH 构造的精确顺序

启动路径对 PATH 的设置为：

```bash
PATH=/root/.headroom/bin:/opt/node-v22/bin:$PATH
```

注意顺序：`/root/.headroom/bin`（包含 `rtk`）在 `/opt/node-v22/bin`（包含 `node` 和 `codex`）之前。这确保了 `rtk` 工具优先被找到，同时 Node 环境也完整可用。在新机器上手动调试时，如果省略或错误拼接这两段路径，会导致 `codex` 或 `rtk` 找不到，进而使 Codex 启动脚本 `scripts/launch_autodl_codex_gpt54.sh` 在 PATH 阶段失败。

## 六、screen 会话名称的固定性

代理的 screen 会话名固定为 `hrzh_demo_8790`，这不是随机生成的。命名规则体现了两层信息：项目标识（`hrzh_demo`）和端口号（`8790`）。在多人协作的 AutoDL 环境中，固定命名使任何队友都能用相同命令附加到正确会话，而无需查询会话 ID。
