kompress-zh 评测环境搭建与基线测试执行说明

本说明面向首次运行 kompress-zh 评测的工程师，详细描述在一台全新评测机器（推荐配置为十六核 CPU、64 GB 内存、500 GB 固态硬盘，操作系统要求 Ubuntu 22.04）上从零搭建完整评测环境并执行基线测试的全部操作，共分八个步骤。步骤之间存在明确的前置依赖关系，须严格按照以下顺序逐步执行，任何步骤失败时不得跳过并直接推进至下一步，须根据错误提示完成修复后重新执行该步骤。

第一步：克隆评测框架仓库

执行命令：git clone https://git.internal.example.com/kompress-zh-eval.git /workspace/kompress-zh-eval && cd /workspace/kompress-zh-eval && git checkout release/v1.2

本步骤将评测框架仓库克隆至目录 /workspace/kompress-zh-eval，并将工作区切换至 release/v1.2 分支。该仓库包含后续全部步骤所依赖的脚本文件、配置文件模板以及 Python 依赖清单，是整个流程的起点和基础，必须作为第一步最先执行。克隆完成后应验证 /workspace/kompress-zh-eval 目录内文件已完整到位，再继续执行第二步。

第二步：安装系统级依赖

执行命令：sudo apt-get update && sudo apt-get install -y python3.11 python3.11-venv python3-pip cmake libssl-dev redis-server screen

本步骤安装所有运行评测所需的系统级软件包。其中 cmake 的安装是关键项，因为第三步需要通过源码编译安装 sentencepiece 包，cmake 是该编译过程的必要工具，若 cmake 未安装则第三步的 pip install 将在 sentencepiece 编译阶段报错失败。redis-server 安装后由 systemd 自动启动，默认监听地址为 127.0.0.1:6379，为第五步的环境自检以及后续评测过程提供缓存服务。screen 工具用于第六步创建持久后台会话，确保评测主进程在 SSH 连接意外断开时不被终止。

第三步：创建 Python 虚拟环境并安装所有依赖

执行命令：python3.11 -m venv /workspace/kompress-zh-eval/venv && source /workspace/kompress-zh-eval/venv/bin/activate && pip install -r requirements-eval.txt

Python 依赖清单文件 requirements-eval.txt 位于仓库根目录，在第一步克隆完成后即可访问使用。完整的依赖安装过程通常需要五至八分钟时间，请耐心等待安装完毕。全部依赖包安装成功（脚本退出码为 0）后，方可进入第四步进行参数配置。若 sentencepiece 包的编译过程出现 cmake not found 错误提示，须检查第二步是否已成功安装 cmake，修复后重新执行本步骤直至成功。

第四步：配置评测参数文件

执行命令：cp /workspace/kompress-zh-eval/config/eval_params.template.yaml /workspace/kompress-zh-eval/config/eval_params.yaml && nano /workspace/kompress-zh-eval/config/eval_params.yaml

须在配置文件 eval_params.yaml 中认真填写以下关键字段：baseline_api_url（原始 codex 不压缩通道的 API 端点地址）、compressed_api_url（headroom-zh 压缩通道的 API 端点，默认值为 http://127.0.0.1:9087/v1）、openai_api_key（用于 API 请求的身份鉴权，若留空则第五步自检时将以错误退出）、eval_timeout_seconds（每道题的最长推理等待时间，建议设置为 120 秒）、result_output_dir（评测结果文件的输出目录，建议设置为 /workspace/kompress-zh-eval/results/）。配置文件全部填写完毕并保存后，方可进行第五步。

第五步：执行环境自检（Level 1 Smoke）

执行命令：source /workspace/kompress-zh-eval/venv/bin/activate && python scripts/env_check.py --config config/eval_params.yaml

自检脚本将依次执行九项检查，验证评测环境的基本就绪状态：包括 baseline_api_url 和 compressed_api_url 两个 API 端点的网络连通性验证、openai_api_key 的有效性验证、Redis 服务的连接状态（目标地址 127.0.0.1:6379）、结果输出目录的写权限等重要项目。只有在脚本退出码为 0（全部九项检查均通过）的情况下，才能进入第六步启动评测主进程。若退出码非 0，必须根据错误输出逐项修复配置问题，修复完成后重新执行本步骤，不得绕过自检直接进入第六步。

第六步：在 screen 会话中启动评测主进程

执行命令：screen -S kompress-eval && source /workspace/kompress-zh-eval/venv/bin/activate && python scripts/run_eval.py --config config/eval_params.yaml --task-set AC --output-dir /workspace/kompress-zh-eval/results/

评测主进程在名为 kompress-eval 的 screen 持久会话中运行，这样即使 SSH 连接意外中断，评测进程也会继续在后台执行，不会因网络中断而丢失进度。命令参数 --task-set AC 表示本次评测同时执行任务 A（中文日志排错题，共五题）和任务 C（多步操作指令复述题，共五题），合计十道题。整个评测过程预计耗时二至四小时。若需在评测过程中查看实时进度，可通过命令 screen -r kompress-eval 重新接入 screen 会话进行观察。本步骤须在第五步 Level 1 Smoke 自检以退出码 0 通过后方可执行。

第七步：评测完成后导出结果报告

执行命令：source /workspace/kompress-zh-eval/venv/bin/activate && python scripts/gen_report.py --result-dir /workspace/kompress-zh-eval/results/ --output /workspace/kompress-zh-eval/report/eval_report_AC.html

本步骤须在第六步评测主进程正常退出（退出码为 0，screen 会话内出现"评测完成"提示信息）之后方可执行。若评测进程仍在运行当中，提前执行 gen_report.py 将触发"results incomplete"错误提示并以退出码 2 退出，此时应继续耐心等待评测进程自然结束，不可强行提前生成不完整的报告文件。

第八步：校验报告完整性并打包归档

执行命令：python scripts/validate_report.py --report /workspace/kompress-zh-eval/report/eval_report_AC.html && tar -czf /workspace/kompress-zh-eval/report/eval_report_AC_$(date +%Y%m%d).tar.gz /workspace/kompress-zh-eval/report/

校验脚本 validate_report.py 检查报告文件中的题目数量是否与 _manifest_AC.json 中定义的十道题完全一致，并确认各题分数字段均已填写完整。校验通过后随即执行打包归档操作，归档文件名包含执行日期后缀，便于后续版本管理与历史存档查询。本步骤须在第七步报告文件生成完毕后执行。
