# kompress_zh 准确率保持评测方案 —— 构思与审核纪要

> 本文件记录「构思 Agent」与「评委 Agent」围绕评测方案的多轮迭代过程。
> 迭代目标：为 headroom-zh 的 `kompress_zh` 中文压缩通道设计一套**低成本、可自圆其说**的评测方案，
> 证明"在大幅压缩 token 的前提下，中文上下文任务的效果/准确率不降或降幅有限"。
> 最终定稿见同目录 [`评测方案_v1.md`](./评测方案_v1.md)。

- 编排者：主 Agent（负责跨轮传递上下文、汇总、落盘）
- 参与方：构思 Agent（设计方案）、评委 Agent（严格审查、给改进建议、给结论）
- 收敛判据：评委 Agent 给出 `[结论: 通过]`
- 迭代结果：**2 轮收敛**（第 1 轮"需修改" → 第 2 轮"通过 + 2 条定稿前必落实条件"）
- 关键事实依据：构思/评委 Agent 均核对过仓库真实源码与文档，确认 `kompress_zh` 实际压缩的是
  `tool_result` 中"中文占比高、单块 ≥500 字"的长文本（路由逻辑：`content_router.py` 的
  `_is_chinese_dominant_text` + `min_chars_for_block_compression=500`），方案据此设计材料形态。

---

## 第 1 轮

### 构思 Agent · 初稿（要点）

- **任务设计**：4 类 × 5 题 = 20 题
  - A 长中文日志排错（自造，埋错误码/路径/端口）
  - B 中文交接文档 QA（真实文档 `HEADROOM_ZH_AUTODL_REPRO_GUIDE.md`，端口 8790 等锚点）
  - C 多步指令复述/重排（自造阶梯，顺序约束）
  - D 中文笔记语义抽取（真实 `STATUS` / `integration_notes`，三分类：已验证/不应沿用/不确定）
- **对比方案**：Baseline（原始 codex 不压缩）vs Headroom_zh（压缩）；控制变量 temp=0、prompt 逐字一致、
  注入方式一致、唯一变量=是否压缩；约 50 次 LLM 调用。
- **指标**：锚点命中率（自动）+ 任务正确率（人工二值）+ 质量 1–5 分（可选）+ 匿名混合判分；
  token 节省用内置 `compression_ratio` 或 dashboard 字节。
- **呈现**：主结果对照表 + 双轴柱状图 + 单案例 before/after 卡片。
- **时间成本**：约 7–10 人时。

### 评委 Agent · 第 1 轮审查（结论：需修改）

核对了仓库真实文档，确认材料假设可落地（端口/路径/命令/否定限定语义都真实存在），肯定了
目标定位准、范围自我设限合理、控制变量意识到位、时间预算诚实。但指出三条**会被答辩评委一问就破**的硬伤
+ 四条次要项：

| 编号 | 级别 | 问题 | 改进方向 |
|---|---|---|---|
| **S1** | 严重 | 缺"压缩破坏对照"，指标无区分度。两组若都接近满分，无法排除"题目送分、压不压都对" | 增设 `headroom_zh-aggressive` 破坏组（激进参数把锚点段也压掉），只跑 A/C 共 10 题，预期明显掉点，反向证明指标有分辨力；放主表正中作"指标自检"。成本 +10 调用 +0.5h，比加样本量更有说服力 |
| **S2** | 严重 | baseline 虚高/虚低的因果方向没讲清。baseline 吃完整长上下文、压缩组吃压缩后短上下文，"持平"可能被解读成"靠删信息去噪让弱 baseline 被淹没"；"输了"又没有可接受下降阈值 | 公平性口径写进正文（只删冗余不删锚点、两组消费必要信息相同）；用破坏组反证去噪论；设定可接受下降阈值写进 PPT 口径 |
| **S3** | 严重 | 锚点命中率与任务答对被并列，关系未论证（前者是对压缩器的度量，后者才是对效果的度量） | 钉死主指标=任务正确率，锚点保留率=解释性辅助；画因果链"锚点保留率 X% → 正确率 Y% → 未损害任务所需信息" |
| M1 | 中 | 自造材料 A/C"精确埋点"有送分/作弊嫌疑（占 10/20 且最像理想输入） | 改"先答案后成文"、全材料公开、A/C 难度可控与 B/D 真实代表性互补定位 |
| M2 | 中 | 重复次数偏弱，temp=0 的"伪确定性"未交代；但别改过头 | 全 20 题各跑 2 次核验一致性，不一致单独标注，n=2 即止 |
| L1 | 轻 | 质量 1–5 分、双轴图是过度设计 | 删质量分（最多保留三档且不进主结论）；双轴图改破坏组对比小柱图 |
| L2 | 轻 | 压缩率口径混用（token 比 vs 字节比） | 主口径钉死节省 token%，字节口径仅单案例卡片标注"仅示意" |

## 第 2 轮

### 构思 Agent · 第 2 版（逐条修订）

按 S1/S2/S3/M1/M2/L1/L2 逐条吸收，修订点以"【针对Sx】"小标注嵌入对应章节。核心变化：

- **【S1】** 第三章新增 `Headroom_zh-aggressive` 破坏档（仅 A/C 10 题），主表正中设"指标自检行"。
- **【S2】** 公平性口径写进正文（只删冗余不删锚点、必要信息相同）；用破坏组构造对"靠删信息去噪取胜"的
  反证（删得更狠反该更干净，事实掉点 → 证伪去噪论）；4.3 设可接受下降阈值。
- **【S3】** 全文钉死主指标唯一=任务正确率（人工二值），锚点保留率仅解释性辅助；画因果链。
- **【M1】** A/C 改"先答案后成文"，锚点与冗余混排，全材料公开，A/C 与 B/D 互补定位。
- **【M2】** 全 20 题 temp=0 各跑 2 次核验一致性，不一致单独标注，n=2 即止。
- **【L1】** 删质量 1–5 分；双轴图改破坏组对比小柱图。
- **【L2】** 主口径钉死节省 token%，字节口径仅卡片示意。
- 时间成本：约 100 次调用、7.5–8 人时（破坏组净增约 +20 调用/+0.5h），仍在原区间内。

### 评委 Agent · 第 2 轮复审（结论：通过）

逐条核对：S1/S2/S3 **已实质解决**（S2 的破坏组反证被评为本版亮点）；M1/L1/L2 已解决；
M2 部分解决（仅表述冗余残留）。同时指出第 2 版引入/残留需在**定稿前落实**的事项：

| 事项 | 级别 | 内容 |
|---|---|---|
| 破坏组可行性兜底 | **必改（定稿前）** | 必须交代"把锚点段也压掉"如何实现。隐患：若压缩器天生倾向保锚点，单纯调高压缩档位未必删得到锚点 → 破坏组不掉点、反证落空；若靠手工删锚点，则不再是"同一压缩器不同档位"，公平性打折。兜底：优先用同一压缩器的激进档/降低锚点保护参数；若该档删不到锚点，则退化为"手工移除锚点段后再压"并**如实标注为人工构造的下界对照** |
| 双阈值口径澄清 | **必改（定稿前）** | 4.3 "保持度≥90% 且 每类绝对下降≤1 题"两个粒度不同：单类 5 题里错 1 题=降 20%，本身就破 90%。须写明"90% 是总体口径、≤1 题是单类口径" |
| 正文去重 | 锦上添花 | "破坏组反证去噪"在多节重复，PPT 收敛为一处定义、他处引用 |
| 判分盲法范围 | 锦上添花 | 组员判自造题时记得标准答案，"盲"的是组别归属而非题目答案，注明即可 |

> 评委倾向给通过，并把上述两条"必改"作为定稿前必须落实的附带条件，认为它们属"补一两句说明即可"
> 的表述级问题，不构成需要再开一轮的结构性返工。

**`[结论: 通过]`**
