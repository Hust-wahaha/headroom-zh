## 一、评测目标

证明：在 `kompress_zh` 大幅节省 token 的前提下，中文上下文任务的**任务正确率不降或降幅有限**。

- 范围：仅限"中文为主的工具输出 / 长文本"上下文（即 `kompress_zh` 实际生效的场景）。英文场景上游已有评测，不在本次范围。
- 唯一变量：是否 / 多激进地经 `kompress_zh` 压缩。
- 三组对比（见第三章），其中"破坏组"专门用于自证指标有区分度。
- **主指标只有一个：任务正确率（人工二值判分）。** 锚点保留率是"对压缩器的度量"，仅作解释性辅助指标，
  用于画因果链、解释结果，不与正确率并列下"效果不降"的结论。

> 落地前提（与源码一致）：`kompress_zh` 只压缩 `tool_result` 中"中文占比高、单块 ≥500 字"的长文本
> （路由：`content_router.py` 的 `_is_chinese_dominant_text` + `min_chars_for_block_compression=500`）。
> 因此所有评测材料必须是"会被真正路由进 kompress_zh 的形态"：足够长、中文为主、混有路径/命令/端口/数字等锚点。

## 二、评测任务（4 类 × 5 题 = 20 题）

| 类 | 内容 | 能力类型 | 材料来源 | 定位 |
|---|---|---|---|---|
| A | 长中文日志排错（识别出错步骤 + 错误码 + 路径 + 端口） | 长上下文抽取 + 排错 | 自造 | 难度可控 |
| B | 中文交接文档 QA（`HEADROOM_ZH_AUTODL_REPRO_GUIDE.md`，端口 8790 / 路径 / 命令 / 环境变量锚点） | 定向事实抽取 + 锚点保真 | 真实文档 | 代表性 |
| C | 多步指令复述 / 重排（阶梯顺序约束 + 命令原文 + 顺序依赖推理） | 多步推理 + 顺序保真 | 自造 | 难度可控 |
| D | 中文笔记语义抽取（`STATUS` / `integration_notes`，三分类：已验证 / 不应沿用 / 仍不确定） | 否定/限定语义保真 | 真实文档 | 代表性 |

**造题规范（消除送分/作弊嫌疑）：** A/C 自造材料采用"先答案后成文"流程——
1. 先写任务问题与标准答案（含锚点清单）；
2. 再把这些事实**自然融入**一段连贯中文，**不刻意为压缩器摆好锚点位置、不使用突兀的标签化埋点**；
3. 锚点散布在正文中，与冗余叙述混排，贴近真实长上下文。

**定位话术（写进 PPT）：** A/C 自造负责"难度可控、便于设计对照"，B/D 真实文档负责"代表性"，二者互补，
不是为了送分。**全部题目材料、标准答案、锚点集作为交付物公开**（见第八章），接受复核。

## 三、对比方案（三组）

| 组 | 配置 | 跑题范围 | 用途 |
|---|---|---|---|
| Baseline | 原始 codex，不压缩，吃完整长上下文 | 全 20 题 | 效果基准 |
| Headroom_zh（正常档） | `kompress_zh` 默认参数，只删冗余、保锚点 | 全 20 题 | 主对比 |
| **Headroom_zh-aggressive（破坏档）** | 激进压缩，强行把锚点段也压掉 | 仅 A/C 共 10 题 | 指标自检（反证） |

### 3.1 破坏组的作用（解决"指标无区分度"）

若 Baseline 与正常档都接近满分，无法排除"题目送分、压不压都对"。破坏档刻意把锚点也压掉，
**预期正确率与锚点保留率明显下降**，用以反向证明：指标本身能区分"信息有损 / 无损"——一旦真删了关键信息，
正确率立刻掉，说明满分不是题目送分。只需跑锚点最关键的 A/C 共 10 题即可暴露差异，成本约 +20 次调用 / +0.5h，
比盲目加样本量更有说服力。破坏档结果置于主结果表正中作"指标自检行"。

### 3.2 破坏组实现方式与兜底（定稿补丁 · 必落实）

破坏档是整套反证的支柱，必须保证"真能把锚点删掉"，否则反证落空或公平性打折。实现按优先级：

1. **首选：同一压缩器的激进档。** 调高压缩比 / 降低锚点保护相关阈值，让 `kompress_zh` 在同一通道下更激进地压缩。
   跑通后**人工抽查破坏档输出是否确实丢失了锚点**。
2. **兜底：若激进档仍删不到锚点**（压缩器天生倾向保锚点），则退化为"**手工移除材料中的锚点段后再走压缩**"，
   并在结果与 PPT 中**如实标注为"人工构造的下界对照（非同一压缩器档位）"**，仅用于展示"锚点缺失 → 掉点"的因果，
   不主张它代表压缩器的真实行为。
3. **极端情况：若连破坏档都不掉点**，则据实承认本批题目偏易、区分度不足，并在结论中说明，而非掩盖。

### 3.3 公平性口径（写进正文，非埋在风险里）

- **两组消费的必要信息相同**：正常档"只删冗余、不删锚点"，Baseline 与正常档拿到的"任务所需必要信息"一致，
  差别仅在冗余叙述被压掉。
- **正面回应"靠删信息去噪"质疑**：正常档若持平，是**信息无损压缩**（锚点保留率高 + 关键事实题答对），
  而非"删信息去噪让弱 baseline 被淹没"。
- **破坏组提供反证**：删掉锚点立刻掉点 → 证明正常档的"持平"来自保真；若仅靠去噪取胜，删得更狠的破坏档反该更"干净"、
  不该掉点，事实掉点则证伪去噪论。

### 3.4 控制变量

`temperature=0`、prompt 逐字一致、系统提示一致、注入方式一致（材料均以"工具输出"形式注入，确保实验组真正触发
`kompress_zh`）；唯一变量 = 是否 / 多激进地压缩。

## 四、评分与度量

### 4.1 主指标（唯一结论性指标）

**任务正确率 = 人工二值判分（对 / 错）**，每题给明确 rubric（如 A："是否正确指出出错步骤 + 错误码"；
C："步骤顺序是否正确"；D："三分类标签是否判对"）。

**因果链（PPT 一句话讲清主辅指标关系）：**
> 压缩后**锚点保留率 X%** → **任务正确率 Y%**（vs Baseline Z%）→ 压缩**未损害完成任务所需信息**。

### 4.2 辅助 / 解释性指标

- **锚点保留率（自动统计）**：每题预列"必须出现的锚点集合"（如 `8790`、文件路径、`HEADROOM_REQUIRE_RUST_CORE=false`、
  错误码等），用关键字精确匹配统计命中数 / 总数。**仅解释"压缩器删了什么"，不单独下"效果不降"结论。**
- 与正确率**配对呈现**，回应"锚点在但没用对 / 锚点丢但蒙对"的质疑：让评委看到二者一致变化
  （破坏组锚点掉、正确率也掉），从而支撑因果链。

### 4.3 可接受下降阈值（写进 PPT 口径）

预先设定"持平"判据，避免事后找补。**两个门槛粒度不同，分别声明：**

- **总体口径**：保持度 = 正常档总体正确率 / Baseline 总体正确率 **≥ 90%**。
- **单类口径**：每一类（5 题）**绝对下降 ≤ 1 题**。

同时满足 → 判为"持平 / 降幅有限"。
（注：单类 5 题错 1 题即降 20%，故单类不套用 90% 口径；90% 仅用于 20 题的总体层面，二者粒度不同、互为补充。）

### 4.4 一致性核验

交代 `temperature=0` 的"伪确定性"——上游模型推理与 `kompress_zh` 压缩模型推理均可能有轻微抖动。
故**全部 20 题在 temp=0 下各跑 2 次**核验一致性；两次不一致的题**单独标注**，不计入"稳定结论"。
**n=2 即止**，课设不追求统计显著性，不再加重复。

### 4.5 删除项（避免过度设计）

**删除质量 1–5 分**（主观、判分贵、对"证明不降"贡献低）。如确需主观补充，仅保留三档
"明显更差 / 相当 / 明显更好"，且**不进主结论**。

### 4.6 判分盲法

baseline 与 headroom_zh 的答案**匿名混合后再判分**，判分者不知该样本来自哪组，避免主观偏向压缩组。
**说明范围：盲的是"组别归属"，不是"题目标准答案"**（组员判自造题时通常记得答案，这不影响"组间盲判"防偏向的核心目的）。

### 4.7 压缩率口径

**主口径钉死为"节省 token %"**（由 `compression_ratio` 反推），主结果表只用 token 口径。
字节口径（如案例 14342 → 4200，≈ 省 71%）**仅在单案例 before/after 卡片**直观展示，并标注"**字节，仅示意**"。

## 七、风险与取舍

| 风险 / 不严谨处 | 应对 | 为何对课设可接受 |
|---|---|---|
| 两组都满分、无区分度 | 破坏组反证指标灵敏；若连破坏组都不掉点则据实承认题偏易 | 课设只需"有数据、能自圆其说" |
| "靠删信息去噪"质疑 | 正文公平性口径（只删冗余不删锚点）+ 破坏组反证 | 因果讲清后说服力足够 |
| 破坏组未必删得到锚点 | 3.2 兜底：激进档→抽查→必要时退化为人工移除并标注下界对照 | 退化方案如实标注，不夸大 |
| 主辅指标混淆 | 全文钉死主指标 = 正确率，锚点保留率仅解释性 | — |
| 自造题送分质疑 | 先答案后成文 + 全材料公开 + A/C 与 B/D 互补定位 | 真实文档负责代表性 |
| temp=0 伪确定性 | 各题跑 2 次、标注不一致；n=2 即止 | 不追求统计显著性 |
| 过度设计 | 删质量分与双轴图；压缩率主口径只用 token% | 省时 |
| 样本量小、无统计显著性 | 明确标注为小样本演示 | 课设硬约束接受 |
| 只测中文工具上下文 | 范围声明清楚（kompress_zh 目标场景） | 英文上游已有评测 |
